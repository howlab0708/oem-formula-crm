# OEM 처방 상담 콘솔

건강기능식품 OEM 영업팀이 고객 상담 자리에서 바로 쓰는 처방 레퍼런스 검색 · 시장 배합 분석 · 브리핑 도구.
기존 `oem_consulting.html` 단일 파일 프로토타입을 Next.js(App Router) + React 19 + Tailwind CSS v4 컴포넌트 구조로 다시 만든 것이다.

## 실행

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm run start
```

`.claude/launch.json` 의 `dev` 설정은 3100 포트로 뜬다.

## 주요 결정

**CSV 파싱은 워커에서 (`src/workers/csvParser.worker.ts`)**
식약처 품목제조보고 원본은 수만 행이다. 디코딩 → 토크나이즈 → 도메인 변환을 전부 워커에서 끝내고
메인 스레드에는 진행률과 완성된 배열만 넘긴다. 2만 행(EUC-KR 4MB) 기준 약 1.5초, 그동안 필터 입력과
스크롤은 그대로 동작한다. 인코딩은 UTF-8 로 엄격 디코딩해 보고 실패하면 EUC-KR 로 되돌린다(수동 지정도 가능).

**목록은 가상 스크롤 (`src/components/ReferenceGrid.tsx`)**
`@tanstack/react-virtual` 로 보이는 구간만 렌더한다. 2만 행에서 DOM 노드가 약 800개로 유지된다.
대시보드 아래에서 목록이 시작하므로 `scrollMargin` 을 `ResizeObserver` 로 계속 재측정한다.

**기준규격 한 칸에서 지표성분과 규격을 함께 뽑는다 (`parseSpecification`)**
원본에는 규격(내용량) 열이 아예 없다. 대신 기준규격이
`4. 칼슘 : 표시량(285.9mg/1500mg)의 80~150%` 형태라, 괄호 앞이 지표 함량이고 뒤가 1회 섭취 규격이다.
이 표기가 원본의 78% 에 있어서, 항목별로 쪼개 이름·수치·단위를 읽고 분모를 규격으로 쓴다.
성상·대장균군·붕해시험처럼 지표성분이 아닌 품질 항목은 이름으로 걸러낸다.
유산균은 `1,000억 CFU` / `2.0 X 10^11 CFU/g` 처럼 단위가 흔들려서 절대 개수로 환산해 저장하고,
화면에 보일 때만 억/조 단위로 접는다(그래야 분포 비교가 성립한다).

**원재료 자동 분류 (`src/lib/dictionary.ts`, `src/lib/normalize.ts`)**
원본 `원재료명` 은 주원료·부원료·부형제가 한 칸에 섞여 있다. 세 신호로 가른다.
1. 원본이 붙여 준 `(고시형)`/`(개별인정형)` 표식 — 원본의 76% 가 갖고 있다
2. 배합비 내림차순 정렬이라는 성질 → 앞자리 원료가 주원료 후보
3. `기준규격`/`주된기능성` 문구에 이름이 등장하면 소구 원료

두 사전이 동시에 걸리는 이름이 많아서(`스테아린산마그네슘` = 부형제이면서 '마그네슘',
`난소화성말토덱스트린` = 기능성이면서 '말토덱스트린') **더 길게 걸린 쪽**을 따른다.
표식만 우선하면 `스테아린산마그네슘(고시형)` 이 주원료로 올라온다 — 실제로 그렇게 됐었다.

부형제(셀룰로오스·스테아린산마그네슘·피막제 등)는 통계에서 제외한다. 그러지 않으면 "다빈도 부원료" 가
전부 부형제로 채워져 상담에 쓸 수 없다. 판정 결과는 이름 단위로 캐시한다 — 사전 매칭이 이름마다
150여 번의 부분문자열 검사라, 캐시가 없으면 집계 한 번에 수천만 번 돌아 화면이 멈춘다.

**브리핑은 한 곳에서 만든다 (`src/lib/export/briefing.ts`)**
화면 · 텍스트 · 이미지 · PDF 가 같은 `Briefing` 객체를 렌더한다. 숫자가 서로 어긋날 수 없다.
이미지/PDF 는 HTML 스크린샷 라이브러리 대신 Canvas 로 직접 그린다(`renderCard.ts`) — 한글 폰트와
레이아웃이 브라우저마다 달라지는 문제를 피하기 위해서다. PDF 는 A4 세로로 잘라 붙이며 JPEG 로 담는다.

**색 정책**
배경 · 표면 · 괘선은 전부 무채색이다. 유채색은 데이터 막대와 현재 선택에만, 단일 계열(blue) 하나만 쓴다.
차트는 대부분 단일 계열이라 범례 대신 제목이 무엇을 그렸는지 말한다. 모든 차트에 '표' 토글이 있어
값이 색·길이로만 전달되지 않는다.

## 지원하는 CSV

헤더를 자동으로 알아본다. 아래 둘 다 그대로 열린다.

| 원본 열 | 쓰임 |
|---|---|
| `PRDLST_NM` 제품명 · `BSSH_NM` 업소명 | 제품명 · 제조원 |
| `PRDT_SHAP_CD_NM` 제품형태 | 제형 (정/캡슐/분말…) |
| `DISPOS` 성상 | 제형 보정 — 경질/연질 구분은 여기에만 있다 |
| `STDR_STND` 기준규격 | 지표성분 함량 + 1회 섭취 규격 |
| `NTK_MTHD` 섭취방법 | 규격 대체 추정 (`1회2캡슐(250mg/1캡슐)` → 500mg) |
| `RAWMTRL_NM` 원재료명 | 주원료/부원료 자동 분류 |
| `PRIMARY_FNCLTY` · `PRDLST_REPORT_NO` · `PRMS_DT` | 주된 기능성 · 신고번호 · 신고일자 |

한글 헤더(`제품명`, `업소명`, `성상`, `기준규격`, `원재료명` …)도 같은 방식으로 인식한다.
7열 템플릿(`제품명, 제조원, 제형, 규격, 주원료, 지표성분 함량, 부원료` — 여러 값은 `|` 로 구분)도 그대로 열리고,
헤더를 하나도 못 알아보면 7열 위치 기반으로 떨어뜨린다. `public/sample-reference.csv` 가 예시다.
화면의 **CSV 내보내기** 는 7열 템플릿으로 저장하므로 그대로 다시 올릴 수 있다.

## 실측 (식약처 품목제조보고 원본, 45,970건 / 82MB)

| 항목 | 결과 |
|---|---|
| 적재 시간 | 19.4초 (개발 빌드, 워커) |
| 적재 중 메인 스레드 | 16ms 타이머 중앙값 17ms · p95 40ms — 멈추지 않음. 마지막 렌더에서 1.7초 한 번 |
| 제형 판별 실패 | 8건 (0.02%) |
| 규격 추출 실패 | 25.9% (원본에 규격 열이 없어 기준규격·섭취방법에서 추정) |
| 지표성분 0개 | 0.4% |
| 주원료 0개 | 3.5% |
| 집계(차트 6종) | 약 0.45초 |
| 목록 DOM 노드 | 약 1,100개 (가상 스크롤) |

## 접근 제한

환경변수 `APP_PASSWORD` 하나로 앱 전체를 막는다. 사람별 계정이 필요 없는 사내 도구라 세션 저장소를
두지 않고, 비밀번호로 HMAC 서명한 값을 HttpOnly 쿠키에 담아 요청마다 다시 계산해 맞춘다
(`src/proxy.ts`, `src/lib/auth.ts`). 비밀번호 자체는 쿠키에 들어가지 않고, 모르면 위조할 수 없다.

- 검사는 서버(Proxy)에서 한다. 개발자도구로 우회되지 않는다.
- 운영에서 `APP_PASSWORD` 가 없으면 **열어 두지 않고** 설정 안내 화면으로 보낸다.
  잠갔다고 믿는 사이 공개돼 있는 상황이 가장 나쁘다.
- 로컬 개발(`npm run dev`)에서는 변수가 없으면 잠금이 꺼진다.
- 통과 쿠키는 30일 유지된다. 비밀번호를 바꾸면 기존 쿠키는 전부 무효가 된다.

Vercel 에서는 Settings → Environment Variables 에 `APP_PASSWORD` 를 추가한 뒤 재배포한다.

## 한계

- 규격의 26% 는 원본에 근거가 없어 비어 있다(규격 열이 없는 데이터셋이다). 이 제품들은 규격 범위 검색에서 빠진다.
- 규격 범위 검색에서 액상은 비중 1로 근사해 mg 으로 환산한다.
- 지표성분은 `기준규격` 문자열에서 정규식으로 뽑는다. 표기가 크게 어긋난 행은 함량 검색 대상에서 빠진다.
- 주원료/부원료 구분은 휴리스틱이다. 배합비 순서가 흔들린 행에서는 어긋날 수 있다.
- 데이터는 브라우저 메모리에만 있다. 새로고침하면 예시 데이터로 돌아간다.
