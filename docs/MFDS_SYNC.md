# 식약처 C003 자동 연동

CSV 선택 없이 C003 품목제조신고 자료를 서버에서 수집한다. 매일 한국 시간 22시대에 실행하며 관리 배포에서는 `지금 업데이트`로 수동 실행할 수도 있다. Hobby의 실행 시각은 22:00~22:59 범위다. 사용자가 브라우저를 닫아도 시작된 서버 작업은 계속된다.

## 운영 설정

다음 값은 **oem-formula-crm의 Vercel Production 비공개 환경 설정**에만 등록한다. 클라이언트 환경 변수(`NEXT_PUBLIC_`)로 만들지 않는다. 실제 값은 소스 코드·문서·채팅·명령 인수·로그에 넣지 않는다.

| 변수 | 설정 |
| --- | --- |
| `MFDS_API_KEY` | 사용자가 C003 신청을 완료한 인증키 |
| `CRON_SECRET` | 독립적으로 생성한 32자 이상의 임의 비밀값. Vercel 예약 실행 인증용 |
| `MFDS_SYNC_ENABLED` | 주 관리 배포만 `1`. 다른 회사 배포는 설정하지 않음 |
| `APP_DATASET_ADMIN` | 회사별 스키마를 쓰는 관리 배포라면 `1` 필요 |
| `POSTGRES_URL` 등 기존 DB 연결 | 기존 설정 유지 |

Vercel Fluid Compute의 300초 실행 시간을 확인한다. 같은 저장소가 `oem-formula-crm-ph`에도 배포되므로, 해당 배포에 `MFDS_SYNC_ENABLED=1`을 중복 설정하지 않는다. 다른 배포는 공유 자료를 계속 조회한다.

환경 설정은 새 배포부터 적용된다. 사용자에게 완료된 변경 내용을 보여주고 배포 승인을 받은 다음 등록·배포한다. 활성화 후 최초 전체 연동에서 정상 종료, 건수, 소요 시간, DB 용량, 두 배포의 조회를 확인한다. 실제 인증키를 이용한 전체 수집 시간은 공개 샘플 테스트로 확인할 수 없다.

## 데이터 보존과 검증

- 현재 4만여 건은 처음 연동하기 전까지 그대로 조회된다.
- C003 전체를 한 번에 최대 1,000행씩 순서대로 수집한다. 현재 공개 응답 46,066건이면 약 47회 수집과 마지막 건수 재확인 1회가 필요하다. 이 숫자는 변동된다.
- 원래 CSV에서 사용한 `rowToProduct` 원료 분류와 표시용 회사명·제품군 정렬을 재사용한다.
- 기존 제품은 고유 신고번호로 연결하고 ID를 유지한다. 새 제품은 제조소 인허가번호와 신고번호로 ID를 만든다. 모기업명으로 공장을 합치지 않는다.
- 기존 브랜드 등 API에 없는 추가 필드는 유지한다. 기존 제조소 번호의 변경, 원료·기준정보 소실, 날짜 후퇴는 중단 사유다.
- API에서 사라진 제품은 취소로 단정하지 않고 기존 자료를 보존한다. 완료 화면에 보존 건수를 표시한다.
- 임시 데이터셋을 수집하는 동안 화면은 기존 데이터셋을 조회한다. 전체 건수·중복·기존 데이터와의 일관성·마지막 원본 건수를 확인하고 한 트랜잭션으로 전환한다.
- 완료된 데이터셋은 수정하지 않고 새로운 버전을 만든다. 세대별 전송 캐시가 기존 자료와 섞이지 않는다.
- 직전 데이터셋은 `archived`로 남긴다. 다음 수집을 준비할 때 이전 보관본을 정리하고 일반 VACUUM으로 공간을 재사용한다. 활성 데이터셋, 배합비, 노트, 원료단가, 즐겨찾기는 삭제하지 않는다.
- 배치 적재, CSV 전환, 자동 연동은 같은 DB 잠금으로 조정한다. 활성 데이터셋에 CSV 배치를 넣을 수 없다.

## 중단과 복구

실행권과 다음 수집 위치를 `oem_sync.runs`에 저장한다. 동시 실행은 막고, 비정상 종료한 실행권은 6분 후 다시 얻을 수 있다. 일시적인 통신 오류나 시간 제한은 이어받을 수 있다. 12시간이 넘은 수집은 식약처 자료 순서가 바뀌었을 수 있어 새로 시작한다. 매일 예약 작업이 다시 확인하며, 화면에서도 재시도할 수 있다.

한 실행은 약 240초 안에 수집을 멈추고 상태를 저장한다. 완료 전에 제한에 도달하면 기존 자료를 유지한다. 서비스 전체에서 최근 1시간 90회까지만 요청하며, 완료 후 1시간 이내 재실행을 제한한다. 다른 프로그램에서 동일 인증키를 사용한 요청은 이 카운터에 포함되지 않으므로 식약처가 추가로 제한하면 그대로 일시 중단한다.

수집 오류는 패널에 표시한다. 잘못된 키, 응답 형식 변경, 중복·건수 불일치는 조치 후 새 수집이 필요하다. 서버 로그와 화면에는 API 주소나 원본 오류 메시지에 포함될 수 있는 키를 남기지 않는다.

이 기능은 C003 제품 레퍼런스의 갱신이다. I-0040/I-0050 기능성 원료의 인정 기준·섭취량을 검토 없이 자동 변경하지 않는다. 자동 실시간 반영이나 제품 판매 지속 여부를 보증하는 기능은 아니다.

## 검증

일반 테스트: `node --test tests/*.test.cjs`

DB 통합 검증: 별도로 설치한 `@electric-sql/pglite` 경로를 `PGLITE_TEST_PATH`에 지정하고 `node --test tests/integration/mfdsSync.cjs` 실행. 테스트는 메모리 PostgreSQL만 사용한다. 운영 비밀번호나 DB 연결값은 필요 없다.

공개 표본 출처: 2026-09-12 `https://openapi.foodsafetykorea.go.kr/api/sample/C003/json/1/5`. 인증키 없는 공개 표본 5건을 `tests/fixtures/mfds-c003-sample.json`에 보관한다. 전체 건수는 표본 응답의 메타데이터이며 전체 수집 완료를 뜻하지 않는다.
