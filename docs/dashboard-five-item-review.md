## 2. 원본 컬럼 확인 및 데이터 설계

### 버그 1: 최소 물리적 단위 중량

실제 C003 헤더는 `LCNS_NO, BSSH_NM, PRDLST_REPORT_NO, PRDLST_NM, PRMS_DT, POG_DAYCNT, DISPOS, NTK_MTHD, PRIMARY_FNCLTY, IFTKN_ATNT_MATR_CN, CSTDY_MTHD, SHAP, STDR_STND, RAWMTRL_NM, CRET_DTM, LAST_UPDT_DTM, PRDT_SHAP_CD_NM`입니다.

| 원본 | 기존 앱 필드 | 이번 사용 |
|---|---|---|
| `NTK_MTHD` | `Product.intakeMethod` | ‘1정당 500mg’, ‘2캡슐(1,000mg)’, ‘1포(3g)’ 등 단위와 중량이 함께 있는 문구 |
| `PRDT_SHAP_CD_NM` | `Product.form` | 제형에 맞는 최소 단위인지 확인 |
| 별도 제공된 1알 중량 열 또는 기존 명시적 환산 | `Product.unitWeightMg` | 이미 검증된 알약 단위 중량 |
| 일반 CSV의 규격/내용량 열 | `Product.weightLabel` | ‘60g(120정)’처럼 물리적 총 개수가 명시된 경우만 역산 |
| `STDR_STND` | `Product.mainDetail` | 성분의 표시량 분모를 1정 중량으로 오인하지 않도록 중량 카드의 직접 근거로 사용하지 않음 |

현재 C003에는 별도의 ‘1일 섭취횟수’, ‘1회 섭취량’, ‘총 정수’, ‘총 포 수’ 열이 없습니다. `POG_DAYCNT`도 개수로 사용하지 않습니다. `weightMg`는 기존에 서로 다른 중량 기준이 섞인 필드라 새 카드에 그대로 사용하지 않습니다.

새 DB 열 없이 `standardUnitWeightMg(product)`로 계산합니다. 향후 구조화된 포장 자료를 받을 때는 공급자가 제공한 `total_content_mg`와 `physical_unit_count`, `physical_unit_kind`, 근거 문구를 별도 필드로 매핑하는 것이 적절합니다. 이번에는 실제로 없는 값을 채워 넣지 않았습니다.

### 버그 2: 권장섭취량 기준

별도 기준 파일 `src/lib/rda.ts`를 추가했습니다. 기준은 보건복지부 **2025 한국인 영양소 섭취기준** 요약표의 ‘권장섭취량(RNI)’ 열입니다. 사용자 요청의 RDA에 해당하는 기준을 사용하고, 충분섭취량(AI), 상한섭취량(UL), 식약처의 기능성 일일섭취량 범위는 대체값으로 사용하지 않습니다. [공식 자료·정오표](https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=167)

| 기준 필드 | 내용·출처 |
|---|---|
| 원료 키 | 비타민C 등 검증된 영양소명과 제한된 동의어 |
| 권장량·단위 | 공식 요약표 5–7, 9–11쪽의 성별·연령별 권장섭취량 |
| 비교 대상 | 성인 남성/여성 각 5개 연령 구간. 임신·수유 기준은 포함하지 않음 |
| 기준 버전·출처 | `2025 한국인 영양소 섭취기준` 및 공식 자료 URL |
| 당량 요구 | 비타민A: RAE, 엽산: DFE 표기를 원문에서 확인해야 비교 |
| 제품의 함량 근거 | `markers`, `mainDetail(STDR_STND)`, `intakeMethod(NTK_MTHD)` |

등록한 기준은 비타민A·B1·B2·B6·B12·C, 나이아신, 엽산, 칼슘, 인, 마그네슘, 철, 아연, 구리, 요오드, 셀레늄, 몰리브덴 17종입니다. 예를 들어 남성 19–29세의 비타민C는 100mg, 칼슘은 800mg, 철은 8mg입니다. 권장섭취량이 없거나 기준 파일에 미등록인 성분, 하루 함량·단위가 불명확한 성분은 비교에서 제외하며 상세 표에 이를 표시합니다.

비타민D·E·K, 비오틴, 판토텐산 등은 이 기준표에서 충분섭취량으로 제시되므로 RDA로 바꾸어 넣지 않았습니다. 엽산의 단순 μg와 μg DFE, 비타민A의 RE와 RAE도 동일하다고 가정하지 않습니다.

### 신규 1: 즐겨찾기 저장

새 서버 테이블 `saved_searches`:

```sql
id             uuid primary key,
owner_key      text not null,           -- 브라우저 비밀 토큰의 SHA-256
scope          text not null,           -- private 또는 team
name           text not null,
filters        jsonb not null,          -- 전체 FilterState
rda_profile    text not null,
generation     text,                    -- 저장 당시 데이터 세대
result_count   integer not null,
created_at     timestamptz not null default now()
```

`filters`에는 검색어, 주원료 목록·모두/하나라도 방식, 제형, 제조원, 부원료 포함/제외, 중량 상하한, 지표성분명·단위·함량 상하한을 보존합니다. 권장량 비교 대상도 함께 저장합니다.

256비트 무작위 브라우저 토큰을 HttpOnly·SameSite=Lax 쿠키에 저장합니다. 운영에서는 Secure 속성을 사용합니다. 서버에는 토큰 자체 대신 해시를 저장하며, 소유자 값을 클라이언트 요청으로 받지 않습니다. 쿠키를 지우거나 다른 브라우저를 쓰면 개인 검색에 접근할 수 없습니다. 기존 공용 로그인은 유지됩니다.

조회는 `owner_key = 현재 브라우저 OR scope = team`, 삭제는 `owner_key = 현재 브라우저`로 제한합니다. 테이블 RLS를 활성화하고 PUBLIC·anon·authenticated 역할의 직접 접근 권한을 제거합니다. 소유자+생성일 및 팀 공개 검색의 생성일 인덱스를 둡니다. 여기서 ‘팀’은 현재 서비스의 공용 로그인 사용자 전체입니다.

API: `GET /api/favorites`, `GET /api/favorites?id=UUID`, `POST /api/favorites`, `DELETE /api/favorites`. 공유 주소는 `/?saved=UUID`입니다. 개인 검색 주소는 같은 브라우저에서만 열립니다. 로그인 전 공유 링크를 열어도 로그인 후 `saved` 값이 유지됩니다.

### 신규 2: 내보내기 설정

서버 테이블은 추가하지 않습니다. 현재 화면의 `logo`, `customer`, `hidden.manufacturerCondition`, `hidden.manufacturers`, `hidden.subExclude` 상태를 사용합니다. 로고는 로컬에서 이미지로 읽어 제한된 크기로 변환하고 PDF·PNG·이미지 클립보드에 함께 그립니다. 외부 이미지 서버로 업로드하지 않습니다.

숨김 대상은 기존 `Briefing.conditions`의 `제조원`·`부원료 제외` 그룹과 `Briefing.topManufacturers`입니다. 먼저 공통 내보내기 객체에서 제거한 뒤 텍스트·이미지·PDF를 만듭니다. 원본 검색 조건과 결과 통계는 변경하지 않습니다. 숨김 때문에 조건 표시가 모두 사라지면 ‘선택한 내부 조건 숨김 · 결과에는 적용됨’이라고 표시합니다.

### 신규 3: 데이터 출처·기준일

`ImportReport.provenance`, `DatasetMeta.provenance`, 기존 서버 `import_status.provenance JSONB NULL`을 추가했습니다.

```json
{
  "source": "mfds-c003",
  "updatedThrough": "2026-09-04",
  "datedRows": 45996
}
```

파싱에 성공한 제품 행의 `LAST_UPDT_DTM`에서 날짜를 확인하여 최댓값과 유효 날짜 행 수를 보존합니다. `PRMS_DT`(신고일), `CRET_DTM`(등록일), 파일명, 현재 시각으로 기준일을 대신 만들지 않습니다. 파일명이 C003이라고만 해서 출처를 확정하지 않고 실제 코드 헤더를 확인합니다.

`updatedThrough`는 **원본 행 최종수정일의 최댓값**이며, CSV 다운로드 날짜나 모든 행의 최신성 보증일이 아닙니다. 헤더 설명에도 이 의미를 표시합니다. 공식 C003 제공 주기는 상시이고 앱에는 자동 갱신 작업이 없으므로 ‘CSV 업로드 시 반영’이라고 표시합니다. [C003 공식 API 안내](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=C003)

과거에 저장된 세대는 이 값이 없으므로 `finished_at`이 있으면 **서버 반영일 기준 (원본 기준일 미보존)**으로 표시합니다. 출처 미확인 CSV는 그대로 미확인이라고 표시합니다. 원본 기준일은 다음 CSV 업로드부터 보존됩니다. 이 문구를 위해 기존 운영 데이터를 임의로 교체하거나 현재 로컬 CSV의 날짜를 과거 세대에 덧붙이지 않았습니다.

## 3. 계산·기능 로직

```text
표준 1회분 중량:
  제형과 일치하는 명시적 단위 중량이 있으면 사용
  또는 명시적 총 질량 / 물리적 총 개수
  일수·섭취횟수는 나눗셈에 사용하지 않음
  부피뿐인 값, 개수 불명, 서로 모순되는 중량, 복합 포장 총중량 제외
  현재 조건의 계산 가능한 제품 중량을 모아 중앙값 계산
  참고 범위 밖 표본 수를 함께 계산하되, 크기만 보고 삭제하지 않음

고함량 비율:
  각 제품에서 현재 선택 지표성분을 우선 사용
  없으면 선택 주원료와 대응하는 지표성분, 주원료 선택도 없으면 전체 지표성분
  각 성분의 표시량 분모와 하루 섭취량 또는 명시된 1일 함량으로 dailyContent 계산
  권장량이 등록되어 있고 단위·당량을 비교할 수 있을 때 ratio = dailyContent / RNI
  비교 가능한 성분이 하나라도 있으면 분모 제품 수 +1
  해당 성분 중 ratio >= 1이 하나라도 있으면 고함량 제품 수 +1
  비율 = 고함량 제품 수 / 비교 가능한 제품 수 × 100
  분모가 0이면 '-' 표시

즐겨찾기:
  저장 입력 검증 → 브라우저 소유자 결정 → 서버 저장 → 고유 URL
  링크 열기 → 기존 로그인 → 공개 범위 확인 → 전체 조건과 RDA 비교 대상 복원
  같은 데이터 세대면 같은 조건으로 계산, 세대가 바뀌면 안내 후 현재 데이터로 계산

내보내기:
```

## 4. 버그 수정 전후와 원인

같은 로컬 CSV 45,996건, 조건 없음으로 비교했습니다.

| 항목 | 수정 전 | 수정 후 | 값이 달라진 이유 |
|---|---|---|---|
| 중량 카드 | 1일 총중량 중앙값 **2,400mg**, 환산 5,996건 | 표준 1회분 중앙값 **1,000mg**, 환산 5,389건 | 하루 여러 번·여러 알의 합산량에서 최소 물리적 단위 중량으로 바뀜. 두 지표는 포함 조건도 다름 |
| 함량 카드 | 공전 상한·하한 사이 위치 중앙값 **16.8%**, 비교 2,006건 | 권장량 100% 이상 제품 **54.7% = 888 / 1,624건** | 원료별 기준 위치를 섞은 중앙값 대신 제품 단위의 조건 충족 비율로 정의 자체를 변경 |

예: `1일 3회, 1회 2캡슐(250mg/1캡슐)`은 종전 하루 총량 1,500mg이지만 새 중량 카드에서는 250mg입니다. 하루 함량 계산에는 여전히 1,500mg을 쓰므로 영양소의 일일 함량까지 1캡슐 함량으로 축소하지 않습니다.

고함량 54.7%는 **남성 19–29세** 기준입니다. 함량 확인 제품 3,556건 중 권장량 비교 가능 1,624건을 분모로 삼으며, 전체 45,996건 중 54.7%라는 뜻이 아닙니다. 16.8%와 54.7%는 서로 다른 지표이므로 증가율로 해석하지 않습니다.

중량 참고 범위 검증:

| 제형 | 새 중앙값 | 단위 확인 표본 | 참고 범위 밖 |
|---|---:|---:|---:|
| 정제 | 800mg | 1,552건 | 159건 (200~1,200mg 밖) |
| 경질캡슐 | 450mg | 595건 | 87건 (300~800mg 밖) |
| 연질캡슐 | 600mg | 880건 | 242건 (300~800mg 밖) |
| 캡슐, 경질/연질 미분류 | 410mg | 25건 | 8건 (300~800mg 밖) |
| 분말 | 3,000mg | 942건 | 정제·캡슐 범위 적용하지 않음 |
| 액상 | 10,000mg | 541건 | 질량이 명시된 표본만 사용. ml를 mg로 추정하지 않음 |

전체 1,000mg은 분말·액상 등을 포함한 현재 조건 전체 제형의 중앙값입니다. 정제만 선택하면 800mg으로 바뀝니다.

범위 밖 원문에는 ‘1정(4g)을 물에 녹여 섭취’, ‘1캡슐(2,280mg)’ 등이 실제로 있습니다. 이런 명시적 원문 값을 임의로 낮추지 않았습니다. 반면 ‘정제+액상 1병 88.24g’ 같은 복합 포장의 병 전체 중량은 1정 중량이 아니므로 새 집계에서 제외합니다.
